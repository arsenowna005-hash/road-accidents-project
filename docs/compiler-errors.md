# Журнал ошибок компилятора (Лабораторная №4)

В процессе выполнения работы мы столкнулись со следующими ошибками TypeScript, которые помогли нам лучше понять типизацию.

| № | Код и сообщение компилятора | Причина | Исправление |
|---|---|---|---|
| 1 | `TS2307: Cannot find module './models' or its corresponding type declarations.` | Файл с моделями был случайно назван `model.ts` (без буквы "s"), а импорт в коде указывал на `./models`. | Переименовали файл `model.ts` в `models.ts` с помощью контекстного меню в VS Code. |
| 2 | `TypeError: (0 , import_api.parseAccident) is not a function` | Код защитников типов (isRecord, isAccident) был случайно вставлен в файл `api.ts` вместо `guards.ts`. | Разделили код: функции-защитники перенесли в `guards.ts`, а функцию `parseAccident` оставили в `api.ts`. |
| 3 | `npm error Missing script: "check"` | Забыли сохранить файл `package.json` после добавления скриптов. | Нажали `Cmd + S` для сохранения файла и перезапустили команду. |
| 4 | Ошибка не возникала, но данные не парсились | В тестовом JSON намеренно убрали поле `location` (для проверки Type Guard). | TypeScript и функция `isAccident` успешно отловили это и вернули ошибку 422, как и было задумано. |
| 5 | Ошибка не возникала, но в ответе был пароль | Использовали сущность `User` целиком вместо DTO. | Применили `toUserResponse` с `Omit<User, "passwordHash">`, чтобы скрыть секретные данные. |

**Вывод:** Строгий режим TypeScript (`strict: true`) и использование `unknown` вместо `any` позволяют отлавливать ошибки еще на этапе написания кода, до запуска программы в браузере.
